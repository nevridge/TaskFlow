# Decisions record

The feature-factory orchestrator reads this file in full when a stage in `../SKILL.md` says to. Stage and step numbers refer to `SKILL.md`, except Stage 0 step numbers, which refer to `preflight.md`.

The orchestrator appends one entry to `decisions.md` each time one of these is passed: the preflight blocker answer, the Resume or Start over answer, the keep or reset answer, the wrong-branch answer, the **Delete them and continue** answer for extra files in a groomed, not started folder (Stage 0 step 6 in `preflight.md`), each stop's answers and outcome, each stop skipped because the issue was groomed and not contradicted by `research.md` (a contradicted groomed story records no skip for stop 1 or stop 2), each skipped area with its reason, the FORMAT-ONLY pass, each budget unit spent, each owner grant of a unit, each **proceed anyway** given at the stop 3 blocker re-check, and the stop 3 answer.

- Stage 0 steps 1 to 5 in `preflight.md` write nothing, with two exceptions: the orphan sweep (step 5 in `preflight.md`) and the halt commit retry (step 3 in `preflight.md`). Answers given there are held and appended at step 6 in `preflight.md`, once the folder exists, so a preflight Stop writes no file. The wrong-branch answer, asked at step 6 in `preflight.md`, is appended with the other held answers (on Start over, once the new folder exists; see the Start over rule in `resume-halt-start-over.md`). The **Delete them and continue** answer, also asked at step 6 in `preflight.md`, is appended with the held answers once the named files are deleted. A **Stop** answer ends the run and is never recorded (halt commit retry, preflight blocker, wrong-branch, groomed folder extra files, stop 3 blocker re-check); the extra-files **Stop** deletes nothing. The Stage 1 line 1 edit of a groomed, not started `research.md` is not recorded. A **Retry the halt commit** answer is not recorded either. **Rejected** at stop 1 or 2 is recorded as that stop's outcome, because the folder exists by then.
- **Changes requested** at stop 1 or 2: when a round ends, one entry gives the stop, "Changes requested" and a one-line summary of the feedback, not the verbatim text.
- **proceed anyway**: the entry lists the blocker issue numbers it covers.
- A stop 3 answer is a new entry every time it is asked, including on a re-run of Stage 8.
- Budget entries read "Spent respec budget" or "Spent correction budget" (with the stage and the reason), or "Granted one more unit of the <respec|correction> budget". Remaining = cap − spent + granted, with the caps from Rules in `SKILL.md`. Count only budget entries, so a repeated stop 3 answer is never counted. A FORMAT-ONLY pass adds no budget entry; the pass is recorded as its own entry.
- The FORMAT-ONLY entry reads "Stage 5, FORMAT-ONLY pass used (no budget)" and is appended before the formatter runs. A record that holds it has used the run's one pass, so the count survives Resume; Start over (`resume-halt-start-over.md`) deletes the record and resets it.
- If a line is a budget entry but its date, stage or budget cannot be read, say so and ask the owner how much of that budget was spent. Never read it as zero. Other malformed lines are ignored.
