# Preflight

The feature-factory orchestrator reads this file in full when a stage in `../SKILL.md` says to.

Stop on any failure. Steps 1 to 5 only read or ask, apart from the orphan sweep and the halt commit retry in step 3; this run's folder does not change before step 6, and the branch and the tree change only through that retry.

1. **Issue.** Use the invocation argument, or ask once "Which GitHub issue is this for? Give a number, or 'none'." With no issue, derive a slug from the feature description, asking for the description if there is none. Read the issue (title, body, state) and stop if it is closed.
2. **Run folder.** Look for `.feature-factory/<issue-number-or-slug>/`. A folder without `research.md` counts as none, even when it holds a `decisions.md`; so does a groomed, not started folder (`run-folder.md`). If one exists, show which files it has, then ask (see the Rules section in `SKILL.md`), offering **Resume from the latest stage** and **Start over**. This is "this run's folder".
3. **Clean tree.** Any uncommitted change stops the run: stage commits would sweep it in.
   - No run folder in step 2 (groomed, not started included): stop and tell the owner to commit or stash.
   - Run folder found in step 2: a halt commit may have failed. If the current branch is not the `Branch:` line of `research.md`, stop, name both branches and commit nothing. Otherwise ask (see the Rules section in `SKILL.md`), offering **Retry the halt commit** and **Stop**. **Retry** runs the halt commit (see Halt in `resume-halt-start-over.md`): on success preflight continues, on failure report it and stop.
   - Neither this offer nor Start over discards a change. A Start over answer from step 2 stays held, so the folder is not deleted before the retry.
4. **Blockers.** Read `repos/{owner}/{repo}/issues/<N>/dependencies/blocked_by` (GitHub's native links, not body text). On Resume, read `decisions.md` first: a blocker listed in a recorded **proceed anyway** entry is covered, so only new blockers are asked about. On Start over no recorded entry counts. Any open blocker that is not covered stops the run and is named. Ask (see the Rules section in `SKILL.md`), offering **proceed anyway** and **Stop**. Continue only on **proceed anyway**, which covers only the blockers listed then.
5. **Orphan sweep.** For each other folder under `.feature-factory/` (skip folders without a `research.md`): a groomed, not started folder is judged only by its issue, deleted when its name parses to an issue number and `gh issue view <number> --json state` gives CLOSED, otherwise kept. Any other folder: read the branch from `research.md` and delete the folder if that branch no longer exists locally or its PR is merged or closed. Never delete this run's folder, named by step 1's issue number or slug.
6. **Branch and folder.**
   - No run folder: on `main`, create a branch `<type>/<issue-number>-<short-slug>` (type `feat`, `fix` or `chore` from the issue; slug a few title words; with no issue `<type>/<slug>`; for example `chore/523-restructure-feature-factory-skill`); any other branch is used as is, whatever its name. Create the run folder; if a folder without `research.md` held a `decisions.md`, delete that file and start a new record. Append the held answers.
   - Groomed, not started folder: create the branch as for no run folder. Never delete `research.md` or `grooming.md`. Ask about any other file, naming each (see the Rules section in `SKILL.md`): **Delete them and continue** (only those files) or **Stop**. Append the held answers.
   - Run folder found (Resume or Start over): the branch is the `Branch:` line of `research.md`. Never create a branch. If the current branch differs, name both and ask (see the Rules section in `SKILL.md`), offering **Check out <recorded branch>** and **Stop**. If the owner declines or the checkout fails, stop. If the recorded branch no longer exists, say so and that deleting the run folder starts a fresh run.
   - Resume: apply the halt-commit rule in `resume-halt-start-over.md`, append the held answers, then continue from the latest stage.
   - Start over: apply the Start over rule in `resume-halt-start-over.md`.
