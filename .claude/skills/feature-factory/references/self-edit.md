# Pipeline-editing runs

The feature-factory orchestrator reads this file in full when `../SKILL.md` says to. `FF` below is `.claude/skills/feature-factory`.

1. **When it applies.** The run's diff changes any file under `FF/**` or `.claude/agents/**` (`git diff --name-only --no-renames main...HEAD`). Check after each `docs` commit (Stage 4 or Stage 7) and after an owner-changes commit (Stage 8), before any later stage. The `--no-renames` flag makes a rename a delete plus an add.
2. **What it means.** The run follows `main`'s version of every stage and agent for the whole run. The orchestrator reads `main`'s `SKILL.md` and reference files, also after a compaction (`git show main:.claude/skills/feature-factory/SKILL.md`). Agent definitions are the ones the session loaded at start, which are `main`'s; the orchestrator never points an agent at its changed definition.
3. **Saving copies.** For each reference or template file under `FF/references/` that the diff changes, save `git show main:<repo-relative path>` to `<run folder>/main/references/<file name>` as soon as the change appears. Use Git Bash for the redirect, or a tool that writes UTF-8 without a BOM and keeps line endings, so the copy is byte-identical to `main`'s file. From then on, pass that copy as the `Template path:` (and as any reference an agent is given) and read it yourself. An agent definition that names a reference file by a fixed path (`test-verifier` and `ci-jobs-by-area.md`, for example) gets the saved copy's path in its prompt, with the instruction to read that copy instead. `FF/SKILL.md` gets no copy (item 2 covers it with `git show main:`). `FF/check-reply.mjs` is saved like a reference file when the diff changes it: `git show main:.claude/skills/feature-factory/check-reply.mjs` to `<run folder>/main/check-reply.mjs`, once and byte-identical (items 4 and 5 apply). For the rest of the run, pipe every reply to `CHECK_REPLY_SINCE=<ms> node <run folder>/main/check-reply.mjs <template-path> <expected-output-path>`; it imports only Node built-ins, so it runs from any folder.
4. **Adds and deletes.** A file the diff adds gets no copy: it has no `main` version and `main`'s skill never names it, so nothing in the run reads it until the first run after merge. A file the diff deletes still gets its copy, saved as usual, and agents keep using it.
5. **Never refreshed.** Save a file's copy the first time the diff changes it. If the copy exists, do nothing; later edits to the working file do not change what agents read.
6. **Orchestrator write.** The saved copies are the named exception to "the orchestrator writes only ...". They are not agent files and not in the `run-folder.md` file table.
7. **Review.** `implementation-validator` and stop 3 review the changed pipeline files as part of the diff; nothing about them is skipped. The orchestrator adds one sentence to the notes' Decisions section and the PR body summary: "Pipeline-editing run: it followed `main`'s skill and agents; the first run after merge tests the new rules."
8. **One-run exception.** A brief may need run-only behaviour (a stage rule the change itself relaxes). Only the owner can grant it, only at stop 2, never at stop 3; stop 3 has no override. A grant is recorded in `decisions.md` (see `decisions-record.md`) and resolves the matching contradiction in the run file check (see `run-file-check.md`).
9. **Known limit.** A resumed run starts a new session, which loads the branch's definitions. The saved copies still cover references, templates and `check-reply.mjs`. The first run after merge is the test of this too.
